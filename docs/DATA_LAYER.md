# طبقة البيانات الدائمة

## النطاق

تستخدم المفكرة SQLite عبر `expo-sqlite@57.0.4` المطابق لـ Expo SDK 57. لا تصل الشاشات إلى SQLite مباشرة؛ المسار هو:

> الشاشة ← `appState` ← repositories ← `src/data/database.ts` ← SQLite

قاعدة البيانات هي مصدر الحقيقة للسجلات الدائمة. مصفوفات `appState` نسخ عرض مؤقتة؛ سجل المحادثة تحديدًا يُضاف إلى الذاكرة فور الإرسال، قبل انتظار الكتابة، ليبقى ظاهرًا حتى عند فشل التخزين.

## المخطط، الإصدار 2

يفتح التطبيق `mofakkira.db`، يفعل `PRAGMA foreign_keys = ON`، ثم يقرأ `PRAGMA user_version`. الترحيل داخل `withExclusiveTransactionAsync`. ينتقل من الإصدار 1 إلى 2، ويمكن تشغيله مرات متعددة بأمان عبر فحص الإصدار و`CREATE TABLE IF NOT EXISTS`.

| الجدول | الحقول | الملاحظات |
|---|---|---|
| `folders` | `id TEXT PRIMARY KEY`, `name TEXT NOT NULL` | لا تُخزّن صفوف «الكل» أو «غير مصنف». |
| `notes` | `id`, `title`, `body`, `folder_id`, `original_folder_id`, `created_at`, `updated_at`, `deleted_at` | الأوقات `INTEGER` بميلي ثانية epoch. معرفا المجلد يقبلان NULL. الحذف الناعم يضع `deleted_at` و`original_folder_id` ويجعل `folder_id` NULL. |
| `tasks` | `id`, `text`, `done`, `created_at` | `done` قيمة SQLite صحيحة 0/1. |
| `chat_messages` | `id TEXT PRIMARY KEY`, `role TEXT CHECK(role IN ('user','assistant'))`, `content TEXT NOT NULL`, `created_at INTEGER NOT NULL`, `sources TEXT NULL` | الزمن epoch بالميلي ثانية. `sources` إما NULL أو JSON لمصفوفة معرّفات الملاحظات. القراءة مرتبة دائمًا بـ`created_at ASC, rowid ASC`. لا يوجد حد لعدد الرسائل. |
| `meta` | `key TEXT PRIMARY KEY`, `value TEXT NOT NULL` | مساحة ترحيلات/بيانات وصفية مستقبلية؛ لا تحمل بذورًا. |

الترحيل v2 يضيف `chat_messages` داخل transaction نفسها، مع قيد الدور، ثم يرفع `user_version` إلى 2. يستخدم `IF NOT EXISTS` لتحمل إعادة المحاولة. المفاتيح الأجنبية في الملاحظات تشير إلى المجلدات مع `ON DELETE SET NULL`. حذف المجلد نفسه يسبقه تحديث صريح لـ`folder_id` و`original_folder_id` لكل الملاحظات الحية والمحذوفة داخل transaction واحدة.

## الترحيل والجاهزية

- يبقى Splash ظاهرًا حتى تحميل Tajawal وفتح/ترحيل SQLite.
- فشل فتح القاعدة أو الترحيل يعرض شاشة خطأ واضحة بدل رسم التطبيق أو الانهيار الصامت.
- عند تهيئة `appState` تُنقّى سلة المحذوفات وسجل المحادثة أولًا، ثم يُحمّل سجل المحادثة مرة واحدة إلى الذاكرة قبل إظهار الواجهة لتجنب الوميض والقفز عند فتح المساعد.
- عند فتح المساعد تنفذ تنقية ثانية للسجل، من دون إعادة قراءة الرسائل من SQLite؛ العرض والإرسال بعد التحميل يعتمدان على حالة `appState` في الذاكرة.
- أداة التطوير المخفية في الإعدادات تستدعي `resetDatabase`، فتسقط الجداول بما فيها `chat_messages` ثم تعيد إنشاء المخطط الفارغ. لا تزرع بيانات مثال في الاستخدام المعتاد.

## المستودعات

- `notesRepo`: list/search، purge، إزالة الصفوف الفارغة، create/update/move/softDelete/restore/permanentlyDelete، وعدادات SQL.
- `foldersRepo`: list/create/rename/remove/count؛ `remove` ذري مع تحديث كل الملاحظات.
- `tasksRepo`: list/create/toggle/remove.
- `chatRepo`: `add` و`listAll` و`purgeOlderThan`. تمر كتابات `add` والتنقية عبر طابور تسلسلي واحد. تحفظ `sources` كـJSON نصي؛ وأي قيمة JSON غير صالحة عند القراءة تعامل كمصادر فارغة بدل إسقاط سجل الرسالة. `listAll` تستخدم ترتيب `created_at ASC, rowid ASC` لضمان الثبات عند تساوي التوقيت.
- أخطاء repositories تُسجل في `console.error` وتُعاد للمستدعي. أخطاء كتابة سجل المحادثة تسجل اسم العملية فقط دون محتوى الرسالة أو المعرفات؛ ولا توقف الدردشة. تعرض عمليات الكتابة التي تمر عبر `appState` التنبيه المؤقت الحالي `تعذر حفظ التغيير. حاول مرة أخرى.`
- البحث يطابق التنفيذ السابق (`title + ' ' + body`, case-insensitive، substring) عبر `lower(title || ' ' || body) LIKE lower(?)` داخل SQLite.
- عدادات «الكل» و«غير مصنف» وكل مجلد تأتي من `COUNT(*)`، لا من عدّ مصفوفة الذاكرة.

## قواعد المجال المعزولة

الدوال في `src/data/rules.ts` لا تعتمد على SQLite:

- `recycleCutoff(nowMs)`: كل حذف أقدم من 30 يومًا قابل للتنقية.
- `chatMessageCutoff(nowMs)`: حد الرسائل الأقدم من 30 يومًا محسوب من وقت كل رسالة؛ يستخدمه إقلاع التطبيق وفتح المساعد. الاستعلام يحذف فقط `created_at < cutoff`، لذا لا تُحذف رسالة عمرها 29 يومًا.
- `isEmptyNote`: العنوان والمتن فارغان بعد `trim`.
- `nextUpdatedAt`: لا يتغير `updatedAt` إلا إذا تغيّر العنوان أو المتن.

## قرارات التشغيل

- أول تشغيل يبدأ بقاعدة فارغة تمامًا: لا seed folders/notes/tasks ولا علامة seeded.
- زر + ينشئ مسودة ذاكرة فقط. أول كتابة غير فارغة تحفظ الصف؛ الرجوع دون كتابة يزيل المسودة بلا أثر.
- الملاحظة المحفوظة التي يفرغها المستخدم (العنوان والمتن فارغان بعد `trim`) تُحذف نهائيًا عند المغادرة، ولا تُنقل إلى السلة. العنوان فقط أو المتن فقط صالحان للحفظ.
- عند الإقلاع تُنقّى السلة القديمة وتُحذف أي ملاحظة حية فارغة بقيت كشبكة أمان.
- سجل المحادثة يحتفظ برسائل المستخدم وردود المساعد الناجحة لمدة 30 يومًا من تاريخ كل رسالة. التحية الثابتة ورسائل التحميل والخطأ وحالة إعادة المحاولة لا تحفظ. رسالة المستخدم التي لا رد لها تبقى حتى انتهاء عمرها لكنها لا تدخل سياق النموذج. لا يوجد مسح تلقائي آخر ولا حد عددي للسجل؛ إعادة ضبط التطبيق في أداة التطوير تسقط الجدول ضمن إعادة ضبط قاعدة البيانات.
- يحفظ المساعد مع رد المساعد الناجح معرّفات المصادر الصالحة كـJSON. حذف المصدر أو نقله للسلة أو إفراغه لا يحذف سجل الدردشة ولا يسبب انهيارًا؛ تُخفى وصلة المصدر فقط.
- محرر الملاحظة يحتفظ بعنوانه ومتنِه في حالة محلية طوال فتح الشاشة؛ تحديث قائمة الملاحظات بعد الحفظ لا يعيد ضبط حقلي الإدخال أو موضع المؤشر.
- تُحفظ التعديلات بعد توقف الكتابة نحو 600ms. وعند رجوع الرأس أو Back المادي أو انتقال التطبيق إلى الخلفية أو إزالة المحرر، يُنفذ حفظ إجباري لأحدث قيم محلية قبل المغادرة قدر الإمكان.
- عمليات كتابة الملاحظة تدخل طابورًا متسلسلًا لكل معرّف. يُحوّل أول حفظ للمسودة إلى إنشاء مرة واحدة قبل انتظار قاعدة البيانات؛ و`notesRepo.create` يستخدم `ON CONFLICT(id) DO UPDATE` كحماية إضافية من تكرار الإدراج.
- تحديث `updatedAt` محكوم بتغير العنوان أو المتن فقط؛ المسودة الفارغة لا تُدرج، والملاحظة المحفوظة التي أُفرغت تُحذف نهائيًا عند المغادرة. العنوان وحده أو المتن وحده كافٍ للحفظ.
